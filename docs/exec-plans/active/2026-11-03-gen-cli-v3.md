## Goal

```text
python scripts/simready_gen.py "Create an 80 x 60 x 10 mm plate with a centered 10 mm through-hole."
    [--model NAME] [--json] [--timeout SECONDS]
```

One command: prompt → copilot LLM → `build_part` → STEP → `analyze_geometry` on that exact
STEP → a short human summary, or with `--json` exactly one JSON object on stdout.

## Reuse — do not re-implement (verified 2026-11-03)

- `CopilotAgent` (`simready/copilot/agent.py:127`): `CopilotAgent(model=...)` reads
  `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` from the env (`.env` via dotenv, as
  `simready/copilot/cli.py` does); `.run(user_message, on_event=cb)` returns `AgentResponse`.
- How to turn the event stream into build calls and pick the final build:
  `tests/test_gen_e2e.py:127–150` (events of type `tool_call` / `tool_result`, name
  `build_part`, matched by `iteration`) and `select_final_build`
  (`simready/gen/verify.py:26`) — a later failed build invalidates the run; never fall back
  to an older artifact.
- `analyze_generated_part(step_path)` (`simready/gen/verify.py:10`) for the final analysis.
  The agent normally analyzes too; the CLI still runs `analyze_generated_part` on the final
  STEP itself so the reported analysis always belongs to that exact file.

## Decided — do not change these

1. Put the reusable logic in **`simready/gen/cli.py`** (function `generate(prompt, *, model=None,
   timeout=...) -> dict` plus `main(argv)`); `scripts/simready_gen.py` is a thin wrapper that
   calls `main` (keeps it importable and testable; the plan names the script path).
2. Result dict / `--json` object keys: `prompt`, `model`, `ok`, `step_path`, `spec`,
   `occ_valid`, `faces`, `analysis_status`, `score`, `iterations`, `error`. Take `faces`,
   `score` and `analysis_status` from what `build_part` / `analyze_generated_part` return —
   read those return shapes in the code, don't guess key names; if a value is not available,
   use `null` and say which in the handoff.
3. Exit 0 only when a final build is OCC-valid **and** its analysis is `ok`. No build, a failed
   final build, or failed analysis → exit 1 with `ok: false` and `error` set. Missing
   `OPENAI_API_KEY` → exit 2 with a one-line message naming `.env.example`.
4. With `--json`, stdout carries only the JSON object; progress and the agent's prose go to
   stderr. Without `--json`: the agent's final text, then a 3-line summary (STEP path, faces +
   OCC validity, analysis status + score).
5. No change to `CopilotAgent`, `build_part`, `select_final_build`, `analyze_generated_part`,
   `simready/copilot/cli.py`, or the Streamlit apps.
6. README: add **one** short paragraph at the end of "### 4. Run the copilot — needs an
   OpenAI-compatible endpoint" (line ~162; section 3 is titled "no LLM or API key", so not
   there) showing the command (same line in PowerShell and Bash). Nothing else in the README.
